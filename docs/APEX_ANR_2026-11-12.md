# Apex ANR and floating dock capture controls — 2026-11-12

> The initial motion adapter and its pixel-difference-only acceptance below
> were superseded by the [beta2 motion correction](ANR_MOTION_FIX_2026-11-12.md).
> Use the separate beta2 portable build for the corrected ANR input convention.

Implemented in the current checkout on top of `8332c8a8`, without committing,
pushing, publishing, or changing the existing installed application or its settings.
The portable candidate is labelled `2.1.5-anr-beta`, not an official upstream release.

## Behavior

- The existing frame generation selectors offer **Apex ANR · Beta** in list and
  node modes, with 2X, 3X, 4X and 6X choices. Defaults and existing backend IDs stay
  unchanged; ANR is the appended backend ID 5.
- ANR's NGX-compatible D3D12 exports are loaded directly from `runtime/anr` by
  absolute path. No OptiScaler or Streamline is added and the original NVIDIA
  DLL is retained separately. NVIDIA's NGX core is unnecessary for an ANR-only graph.
- The existing GPU graph supplies enhanced color, estimated current-to-previous
  motion and proxy depth. These are video estimates, not native game inputs.
  The common batching, timestamps, leases, reset and export paths remain in use.
- SDR uses RGBA8; HDR uses RGB10/PQ. Multi-frame capability is queried from the
  provider. Failed DLL calls invalidate the session and use existing graph recovery.
- The V.B14 native bridge imports guidance in COPY_DEST and restores it. Explicit
  transitions fix the debug-layer state mismatch observed with ordinary NGX
  NON_PIXEL_SHADER_RESOURCE guidance. Input color and generated output retain
  the graph's SRV/UAV contract. There is no new per-frame CPU wait or pixel readback.
- ANR configurations use library v21/session v16 `.anr` files and legacy presets
  v37, allowing an older application to reject unfamiliar settings safely.
- The floating top dock has camera and video icons on the same 32×30 row and
  16-pixel icon grid as its existing controls. There are no button labels or
  recording timer in the dock. Tooltips/accessibility names explain the actions;
  the recording dot and existing recording presentation remain. Screenshot and
  recording are available in minimal/fullscreen views without selecting Pro.
  Recording uses the existing immediate start/stop path, like the shortcut.

application source ZIP and SHA256 sidecars. Extract the portable ZIP and run
**Start Veyra.cmd**. It uses `user-data-anr` beside the executable. Select

verified individually before staging. Newly built executable, shaders, QML,
translations and ANR files have new package hashes. No user settings, test
executables, logs, development dependency trees or provider-generated system
Vulkan loader copy are included in the ZIP. Supplied SDKs, build outputs,
current portable candidate and necessary test evidence are retained.
